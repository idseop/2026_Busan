프로젝트 현황을 브리핑하라. 추측하지 말고 실제 파일을 확인해서 쓴다.

1. `date "+%Y-%m-%d (%a)"`로 오늘을 확인하고, **2026-09-18 접수 마감까지 남은 일수**를 계산하라.
   최종 발표평가 2026-10-29까지 남은 일수도 함께.
2. `docs/01-작전계획.md`를 읽고 지금이 몇 주차이며 이번 주 목표가 무엇인지 확인하라.
3. 실제 진척을 파일로 확인하라:
   - `docs/20-데이터카탈로그/INDEX.md` — 실사 완료 데이터셋 몇 건? GO 판정 몇 건?
   - `docs/30-아이디어/SHORTLIST.md` — 아이디어 후보 몇 개? 확정됐나?
   - `docs/10-현안리서치/` — 리서치 완료 현안 몇 개?
   - `docs/40-기획서/` — 초안 존재 여부
   - `figures/` — 차트 몇 장? (**`00_` 접두사는 파이프라인 테스트물이므로 제외**)
4. `docs/00-공모요강.md`의 "미확인 · 문의 필요" 항목 중 아직 안 풀린 것을 나열하라.

## 출력

```
📅 오늘 · D-N (접수) / D-N (발표평가)
📍 현재 단계 — N주차: <이번 주 목표>

진척
  현안 리서치   N건
  데이터 실사   N건 (GO N / 조건부 N / NO N)
  아이디어      N개 → 확정: <있으면 이름, 없으면 미확정>
  차트          N장
  기획서        <상태>

⚠️ 미해결 문의사항
  - ...

▶ 지금 해야 할 일 (우선순위 3개)
  1. ...
```

일정 대비 늦었으면 **늦었다고 명확히 말하라.** 낙관적으로 포장하지 않는다.
