**대상: $ARGUMENTS** (비어 있으면 `docs/40-기획서/`에서 가장 최근 수정된 문서)

제출 전 자기 검열이다. 목표는 안심이 아니라 **떨어질 이유를 미리 찾는 것**이다.

## 절차

1. 대상 문서를 읽어라.
2. `critic` 서브에이전트를 **3개 병렬로** 띄우되 각각 다른 렌즈를 준다:
   - **A · 데이터 심사자** — 데이터를 정말 확보했는가, 입도가 질문에 맞는가, 5주 안에 되는가
   - **B · 정책 심사자** — 문제 정의가 부산 고유한가, 제안을 행정이 집행할 수 있는가, 기존 정책과 뭐가 다른가
   - **C · 발표 심사자** — 첫 페이지에서 읽히는가, 시각화가 채점 가능한 수준인가, 곤란한 질문에 버티는가
3. 세 비평을 종합하라. **두 명 이상이 지적한 항목은 치명상으로 분류**한다.
4. 문서의 수치·출처를 직접 대조 검증하라 — 출처 없는 수치, 카탈로그에 없는 데이터 인용을 색출한다.

## 출력

```
## 종합 판정 — 1차 통과 가능성: 높음 | 반반 | 낮음

## 치명상 (2인 이상 지적)
1. <지적> → <구체적 수정 방안>

## 개별 지적

## 사실 검증 실패 항목
- 출처 없는 수치 / 카탈로그 미등재 데이터 인용

## 우선순위 수정 3가지
가장 점수를 많이 올리는 순서
```

칭찬으로 채우지 마라. 통과 가능성이 낮으면 낮다고 말하라.
