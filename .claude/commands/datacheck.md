**대상: $ARGUMENTS**

이 아이디어가 데이터 관점에서 성립하는지 **실물로** 검증한다. 이게 이 프로젝트에서 가장 중요한 작업이다.

## 절차

1. 확정 주제를 `docs/30-아이디어/SHORTLIST.md`에서 확인하라.
   인자가 비어 있으면 **아직 실사하지 않은 도메인** 중 번호가 빠른 것부터 한다
   (00_경계 → 02_소비 → 01_외국인 → 03_방문 → 04_숙박 → 05_상권 → 06_접근성).
   **02_소비가 이 주제의 심장이다** — 여기가 동 단위로 안 나오면 주제가 흔들린다.
2. 분석 질문에 답하려면 **어떤 데이터가 필요한지 목록화**하라. 필수 / 있으면 좋음 으로 나눈다.
3. 각 데이터에 대해 `data-scout` 서브에이전트를 띄워 실사하라.
   여러 데이터면 **한 메시지에서 병렬로** 띄운다.
4. 받은 파일은 해당 번호 폴더에 둔다 — `data/raw/0N_<도메인>/`
5. 결과를 `docs/20-데이터카탈로그/INDEX.md`에 등재하라.
   **파일이 없으면 이번에 만든다** (미리 빈 표를 두지 않기로 했다).
   컬럼: 데이터셋명 / 제공기관 / 접근 / 기간·갱신 / 공간입도 / 시간입도 / 행수 / 결합키 / 판정 / 로컬경로 / 실사일.
   기존 행은 보존하고 추가만 한다.
6. 최종 판정을 내려라.

## 판정

- **GO** — 필수 데이터 전부 확보. 입도가 질문에 맞음. → 아이디어 확정 후보
- **조건부** — 결함 1개 이하 + 우회로 명확. → 우회로를 구체적으로 적어라
- **NO** — 필수 데이터 미확보 또는 입도 부적합.
  → 보조 데이터(04_숙박·06_접근성)면 해당 분석 단계를 줄이고 진행한다.
  → **`00_경계` 또는 `02_소비`가 NO면** 메인 주제가 성립하지 않는다.
    입도를 구 단위로 낮춰 질문을 바꾸거나, 예비 주제(고령운전자 × 대중교통 사각지대)로 전환한다.

**공간 입도는 행정동이 기준이다** (하드 룰 12). 더 잘면 행정동으로 집계하고,
더 굵으면(시·구 단위 합계뿐) 그 레이어는 지도에 못 올린다.

## 규칙

- 목록에 제목이 있는 것으로 GO를 주지 않는다. **받아서 열어봐야 GO다.**
- NO를 두려워하지 마라. 지금 NO를 내는 게 3주 뒤 NO를 발견하는 것보다 훨씬 싸다.
- NO일 때 반드시 **대안 데이터** 또는 **데이터가 감당하는 더 낮은 질문**을 함께 제시하라.
- 판정 근거에 실제 확인한 수치(행 수·기간·컬럼)를 인용하라.
