# 부산 신고 정책제안 데이터 실사

현행 분석 질문과 필수 항목은 `docs/30-아이디어/신고데이터-정책제안-실행계획.md`를 따른다. 자료명이나 소개문만으로 확보 완료를 판정하지 않는다.

## 자료 탐색 경로

| 대상 | 공식 출처 후보 | 우선 확인 |
|---|---|---|
| 신고 | data.go.kr, 부산경찰청·부산소방재난본부, bigdata-119.kr, busanbigdata.kr | 위경도·발생일시·유형·부산 전역·기간·신고/출동/사건 단위 |
| 경계 | SGIS, 부산 데이터웨이브 | 행정동 코드·기준일·좌표계·개편 이력 |
| 연령인구 | 주민등록인구통계, KOSIS, 부산 공식 통계 | 동별 기준시점·연령 구간·인구수·행정동/법정동 |
| 상권 | 공공데이터포털 상가(상권)정보, LOCALDATA | 위치·업종·식별자·기준시점·개폐업·스냅샷 |
| 정책자원 | 부산시·구군 및 소관기관 공식 업무·사업 자료 | 업무 근거·기존 활동·지원 범위·운영시간·용량 |

위 경로는 탐색 후보이며 특정 자료의 제공을 보증하지 않는다. 카탈로그가 동적으로 로드되어 정적 요청에 목록이 없으면 제공 부재로 판정하지 않는다. 사용 가능한 검색·브라우저·API·직접 다운로드로 확인하고 실제 실패 사유를 기록한다. 로그인·승인·키가 필요하면 절차와 미확보 상태를 명시한다.

## 실사와 기록

1. 제목·기관·공식 URL과 실제 컬럼 정의서를 확인한다. 소개문의 AI 요약과 실제 컬럼을 구분한다.
2. 전체 원본을 새 파일로 `data/raw/`의 해당 도메인에 저장한다. 기존 파일을 덮어쓰거나 원본을 편집하지 않는다. Windows는 curl.exe 또는 Invoke-WebRequest, 다른 환경은 사용 가능한 다운로드 도구를 사용한다.
3. 가상환경 Python(`.venv/bin/python` 또는 Windows `.venv/Scripts/python.exe`)으로 전체 행 수·인코딩·기간·컬럼 의미·결측·중복·전역 포함을 검사한다. 첫 몇 행 미리보기로 전체 품질을 판정하지 않는다.
4. 좌표계·위경도 역전·부산 밖·경계 위·위치 누락을 확인하고 행정동 코드·기준기간으로 결합을 검증한다. 발생시각과 접수·처리시각을 구분한다. 제외 건수와 원본/집계 건수 일치를 남긴다.
5. 최초 실제 확보 시 `docs/20-데이터카탈로그/INDEX.md`를 만든다. 파일·출처·확보일·원본 해시·기간·공간/시간/개체 단위·컬럼·행 수·품질·결합 키·라이선스·공개 조건을 기록한다. 후보 목록으로 빈 확보 카탈로그를 만들지 않는다.
6. 축별 진행 / 조건부 / 보류를 증거와 함께 보고한다. 조건부에는 필요한 추가 자료·해결 경로·아직 허용하지 않는 분석을 쓴다. 구조 변경이나 주제 확정이 데이터 확보를 의미하지 않는다.

## 결합·해석의 경계

- 동별 연령 구성은 지역 설명변수이며 신고 당사자의 연령이 아니다. 실제 연령대 경계와 다르면 임의로 아동·고령인구를 쪼개 추정하지 않는다.
- 신고를 인구비율로 나누어 연령별 신고를 생성하지 않는다. 연령 집계와 유형 집계를 가짜 교차집계로 결합하지 않는다.
- 상권 축은 동별 업종 구성과 신고 특성을 비교한다. 가까운 점포를 사건 장소로 단정하지 않는다. 최신 점포 자료로 과거 상권을 대체하지 않는다.
- 개인정보·원시 신고 내용·사건 좌표를 Git·웹에 게시하지 않는다. 이용 가능한 공식 자료라도 공개 산출물의 조건은 별도 확인한다.
- 데이터가 부족하면 해당 축의 보류 범위를 밝히고 대체 원본·공식 집계를 제안한다. 현행 주제를 임의로 교체하지 않는다.
