# 부산 데이터 소스 지도 & 실사 절차

## 왜 이 스킬이 존재하는가

Track 1 출품작이 죽는 1순위 원인은 분석력 부족이 아니라 **"좋은 아이디어인데 데이터가 없다"** 이다.
데이터 목록에 제목이 있는 것과, 실제로 파일을 받아 열어보니 쓸 만한 것은 전혀 다르다.
한국 공공데이터에서 흔한 배신:

- 목록엔 있는데 **다운로드가 죽어 있음** / 로그인·기관 승인 필요
- 받아보니 **최신 갱신이 3년 전**
- **집계 단위가 시(市) 전체**라 구·동 단위 분석 불가
- **연 1회 스냅샷**이라 시계열 분석 불가
- 컬럼명만 있고 **값이 대부분 비어 있음**
- 좌표가 없거나 주소가 비정형이라 **공간 결합 불가**

그래서 **아이디어 확정 전에 반드시 실물을 받아본다.**

## 1. 소스 지도

> **아래 URL은 2026-08-19에 HTTP 200을 직접 확인한 것만 실었다.**
> 새 소스를 추가할 때도 반드시 접속 확인 후 등재한다. 검색 결과에 나온 URL을 그대로 믿지 말 것
> (실제로 `bigdata.busan.go.kr`은 검색 결과에 등장하지만 **DNS 자체가 없는 죽은 주소**였다).

### Big-데이터웨이브 — 부산 대표 포털 ★ 1순위
`https://data.busan.go.kr/bdip/`

제공 형식은 FILE / API / LINK / SHP / SHEET / CHART / MAP 7종.
제공기관은 부산시 + 16개 구·군 + 부산교통공사·시설공단·환경공단·상수도사업본부·
도시공사·관광공사·부산연구원·빅데이터혁신센터 등. (기관 목록은 화면에서 확인)

> 총 데이터셋 건수는 **의도적으로 적지 않는다.** 초기 조사 때 얻은 수치가
> 포털 원문에서 확인되지 않아 제거했다. 건수가 필요하면 화면에서 직접 확인하고

### ★ 데이터 오픈랩 / Big-데이터웨이브 — **공식 가점 항목**
`https://busanbigdata.kr/` · `https://busanbigdata.kr/intro-data-lab`

> **이전에 "접근 불가로 가정"이라고 적었던 것은 틀렸다. 공모 서식이 가점을 명시한다.**
> 서식 붙임 4 = "추가 가점 (데이터 오픈랩, Big-데이터 웨이브 사용시 작성)"

| 가점 항목 | 서식이 요구하는 기재 |
|---|---|
| 데이터 오픈랩 방문 | 방문일시 / 방문자 / 사용데이터 |
| Big-데이터웨이브 사용 | 데이터명 + **브라이텍스(Brightics) 사용결과 캡처** |

서식의 활용데이터 표 **예시**가 `동백전 사용내역 / csv / 출처: 부산 빅데이터 오픈랩` 이고,
*"제공한 민간데이터 외 추가 활용한 민간데이터 있을 시 반드시 기재"* 라고 쓰여 있다.
→ **오픈랩은 동백전 같은 민간데이터를 참가자에게 제공한다.**

**작업 방침**
- 분석의 뼈대는 **공개 데이터로 완결**시킨다. 오픈랩 접근이 안 돼도 주제가 무너지지 않게 한다
- 그 위에 **가점 재료를 얹는다** — 데이터웨이브 셀프분석(브라이텍스)은 온라인으로 시도해볼 수 있고,
  오픈랩 방문은 일정만 되면 방문 기록 자체가 점수다
- 오픈랩 데이터를 실제로 쓰면 활용데이터 표의 "출처"에 그대로 적는다

### 전국 — 부산으로 필터링해 쓴다 (전부 200 확인)
| 소스 | URL | 쓸모 |
|---|---|---|

| KOSIS 국가통계포털 | https://kosis.kr | 인구·경제·사회 공식 통계. 시군구 시계열의 기본 |
| SGIS 통계지리정보 | https://sgis.kostat.go.kr | **집계구·행정동 공간통계 + 경계 파일 + API.** 지도 시각화의 핵심 |

### ⚠️ 이 환경에서 접근 실패 — 브라우저로 확인 필요
| 소스 | 증상 |
|---|---|
| `bigdata.busan.go.kr` | **DNS 해석 실패.** 죽은 주소로 보인다. 쓰지 말 것 |
| `www.localdata.go.kr` (지방행정 인허가) | DNS는 되나 443 연결 타임아웃. 인허가 데이터가 필요하면 사람이 브라우저로 받아야 한다 |

기상자료개방포털(`data.kma.go.kr`), 소상공인 상권정보(`sg.sbiz.or.kr`)는 미검증 —
사용 전에 `curl -o /dev/null -w '%{http_code}'`로 먼저 확인하라.

### 공간 경계 파일 (지도 시각화 필수)
- **SGIS**가 1순위 — 행정동/집계구 경계 + 인구 속성을 함께 준다
- 데이터웨이브 SHP 51건, 국가공간정보포털(nsdi.go.kr)
- 좌표계 주의: EPSG:5179(중부원점 GRS80) ↔ EPSG:4326(WGS84). `gdf.to_crs(4326)`

## 1-2. ⛔ 카탈로그는 정적 크롤링으로 탐색할 수 없다 (2026-08-19 검증)

**이 사실을 모르고 `curl`로 카탈로그를 훑으면 "결과 0건"을 받고
"데이터가 없다"고 오판하게 된다. 데이터가 없는 게 아니라 안 보이는 것이다.**

실제로 시도해 실패한 것:

| 시도 | 결과 |
|---|---|
| `curl .../opendata/dataSet.do` | 검색결과 **0건**으로 렌더 (목록이 JS로 로드됨) |
| `dataSet.do?searchKeyword=` / `?srchKwd=` / `?keyword=` | 셋 다 결과 없음 — 쿼리 파라미터 서버렌더 아님 |
| `curl data.go.kr/tcs/dss/selectDataSetList.do?keyword=…` | 응답 **0 bytes** |
| `/bdip/analysis/dataCases.do` (우수사례) | 전체 **0 건**으로 렌더 |

**정적으로 되는 것**: 각 페이지의 존재 확인(HTTP 200), 네비게이션 구조,
설명 문구 등 **서버 렌더된 본문**. 안 되는 것은 **검색·목록 결과**다.

### 그래서 카탈로그 탐색은 이렇게 한다 (우선순위)

1. **`claude-in-chrome` 스킬로 브라우저 자동화** ← 권장.
   JS 렌더 후 화면을 읽으므로 목록·상세·다운로드 링크를 모두 확인할 수 있다.
   *단 확장 프로그램에서 사이트 권한을 미리 허용해야 한다.*
2. **공공데이터포털 OpenAPI** — 서비스키 발급이 필요하고 **사람이 가입·신청해야 한다.**
   키가 생기면 `data/raw/`로 자동 수집이 가능해진다.
3. **사람이 브라우저로 확인** — 데이터셋 상세 URL이나 내려받은 파일을 직접 넘겨받는다.
   가장 확실하고, 초기에 가장 빠르다.

> **개별 파일의 직접 다운로드 URL이 `curl`로 되는지는 아직 미검증이다.**
> 목록 검색이 막힌 것과 파일 다운로드가 막힌 것은 다른 문제다.
> 상세 URL을 하나 확보하면 그때 확인하고 이 문서를 갱신할 것.

## 2. 실사 6단계 — 이 순서를 지킨다

아이디어 하나당 필요한 데이터 각각에 대해 수행한다.

1. **존재** — 목록에서 찾았는가? 제목·제공기관·URL 기록
2. **접근** — 실제로 내려받아지는가? 로그인/승인/API키가 필요한가? **직접 받아본다**
3. **기간** — 시작~종료 연월. 최신 갱신일. 갱신 주기(실시간/월/분기/연/1회성)
4. **입도(粒度)** — 공간 단위(시/구/동/격자/좌표) × 시간 단위(연/월/일/시) × 개체 단위
5. **품질** — 행 수, 결측률, 인코딩(CP949 주의), 컬럼 의미 파악 가능 여부
6. **결합** — 다른 데이터와 이을 키가 있는가? (행정동코드·좌표·업종코드·날짜)

**판정 기준**
- `GO` — 6단계 전부 통과. 바로 분석 착수 가능
- `조건부` — 결정적 결함 1개 이하이고 우회로가 명확 (예: 주소→좌표 지오코딩 필요)
- `NO` — 접근 불가, 또는 입도가 분석 질문에 못 미침

**입도 부적합의 예**: "구별 폭염 취약계층 지도"를 만들려는데 데이터가 부산시 전체 합계 1행뿐 → NO.
질문을 데이터에 맞춰 낮추지 말고, **데이터가 감당하는 질문으로 바꾸거나 다른 데이터를 찾는다.**

## 3. 실사 실행 요령

```bash
# ⚠ 셸에서 curl/wc/python3 가 "command not found" 로 뜨면 PATH 유실이다. 먼저 복구한다.
export PATH="/usr/bin:/bin:/usr/sbin:/sbin:/opt/homebrew/bin:$PATH"

# 파일은 항상 data/raw/ 아래 소스별 폴더에 원본 그대로 저장
curl -sL -o "data/raw/<소스>/<파일명>" "<URL>"

# 인코딩·구조 즉시 확인 (한국 공공데이터는 CP949가 흔하다)
.venv/bin/python -c "
import pandas as pd
for enc in ['utf-8','cp949','euc-kr']:
    try:
        df = pd.read_csv('data/raw/.../x.csv', encoding=enc, nrows=5)
        print('OK', enc); print(df.head()); print(df.columns.tolist()); break
    except Exception as e: print(enc, '실패', type(e).__name__)
"
```

확인 후 **반드시** `docs/20-데이터카탈로그/INDEX.md`에 한 줄 등재한다. 이 표가 단일 진실 원천이다.

## 4. 금지 사항

- 목록 제목만 보고 "데이터 있음"이라고 판단하지 않는다. 받아봐야 있는 것이다.
- 데이터 크기·행 수·기간을 추정해서 쓰지 않는다. 실제 값만 기록한다.
- 원본을 `data/raw/`에서 수정하지 않는다.
- 개인정보가 포함된 데이터는 사용하지 않는다. 공개 배포 가능한 것만 쓴다.
