2026-09-15 검토. 현재 `web/final/data/deep-data.json`의 네 사례와 `case-services.js`, [심층 분석 보고서](부산-119-지도와-심층사례-20260915.md)를 직접 대조했다. 새 외부 자료를 수집하지 않았고 웹 파일은 수정하지 않았다. 아래 문장은 기존 자료를 사용한 화면 설명안이며 새로운 정책 선정 결과가 아니다.

## 설명의 공통 기준

아래 고정 수치는 **2020~2024년 합계·C조건·해당 원문 지역과 세부유형**이다. C는 정상 처리 중 업무운행·훈련출동·구급차소독을 제외한 조건이다. 사용자 필터가 바뀌면 수치 문장은 해당 조건으로 다시 계산하거나 ‘5년 C조건 참고’로 분리해야 한다.

‘질병’은 원문 구급 분류이고 특정 질환·환자의 중증도·예방 가능한 질병이라는 뜻이 아니다. ‘시건개방’은 원문 구조 분류이며 목적이나 긴급성을 이 이름만으로 알 수 없다. 모든 건수는 선택17 완전행의 신고접수 기록이다.

## 필터가 바뀔 때 문장을 만드는 기준

| 정보 | 계산·표시 기준 |
|---|---|
| 지역 전체 지표 | `D.rawRegions`의 선택 연도·조건·구군·원문 동·종별. 세부유형 사례 수치를 지역 전체 건수로 대신하지 않는다. |
| 사례 건수·잔존율 | `case.countsByScope[scope]`의 선택 연도 인덱스. 5년 전체는 합계. 잔존율은 같은 지역·세부유형·연도·조건의 선택17/기본8이며 인구 분모가 아니다. |
| 5년 추세 | 선택 처리조건·해당 사례의 5개 연도. 특정 연도를 고른 상태여도 ‘5년 추세’라는 범위를 명시한다. |
| 사례 시간 | `caseTime`과 `caseMonth`에서 caseIndex·연도·조건을 적용한다. 종별이 사례와 다르면 해당 사례를 선택조건 결과처럼 노출하지 말고 별도 참고 사례로 분리한다. |
| 전체 지역 시간 | `dayHour`, `month`에서 regionIndex·연도·조건·종별을 적용한다. 사례의 ‘질병’과 지역의 ‘구급 전체’ 시간 분포를 혼용하지 않는다. |
| 최다 구간 | 동률이면 모두 제시하거나 ‘공동 최다’를 표시한다. 전체 0이면 최다 구간을 만들지 않는다. 4시간 최대와 8·12시간 최대는 다른 질문이다. |
| 월·요일의 일수당 값 | 선택한 달력연도들의 해당 월·요일 일수로 나눈다. 영업일·생활인구·서비스 대상자 수로 표현하지 않는다. |
| 주민 배경 | 단일 코드 후보와 선택 연도의 12월 말 인구. 5년 전체 선택에서는 2024년 말 참고임을 별도로 표시한다. 인구는 연도 합산하지 않으며 모든 101연령 상세를 유지한다. |
| 복수 인구 후보 | 연산동은 후보별 탐색만 허용한다. 주민 후보를 바꿔도 신고 배정·집계는 바꾸지 않는다. |
| 기존 서비스 | 사례·지역과 관련된 공식 안내를 보여준다. 연도·신고조건을 바꿔도 안내의 확인 시점을 바꾸지 않는다. 2025 안내를 2020 운영 실적처럼 표시하지 않는다. |
| 없는 결과 | 관측 범위가 있는 희소 시간셀 0과 해당 연도에 원문 지역 자체가 없는 상태를 구분한다. 다른 연도·다른 동 자료를 자동 대체하지 않는다. |

네 사례 이외의 원문 동에는 기본 지역 통계·주민 코드 후보는 제공할 수 있다. 확인하지 않은 동별 서비스나 정책 문장을 사례 템플릿으로 복제하지 말고 ‘이 지역의 서비스 대상·운영 범위는 아직 대조하지 않았습니다’로 남긴다.
