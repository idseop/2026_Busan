# 부산 119 지도와 지역별 심층 검토

**현재 화면 변경:** 분석 데이터는 유지한 채 [지도 탐색 앱](부산-119-지도탐색웹-개편-20260915.md)으로 UI를 재구성한다. 아래 화면·검증 기록은 심층분석 도입 당시 버전이며, 최신 UI의 검증과 ZIP은 `data/processed/지도탐색웹-20260915/` 및 `output/부산119-지도탐색웹-20260915.zip`을 따른다.

## 1. 이번에 분석을 더 진행한 부분

기존 17개 컬럼 완전행 704,689건과 2020~2024년 5개년 기준을 유지했다. 새로 추가한 것은 원문 지역×연도×처리조건×신고 종별의 월 분포와 요일×4시간대 교차집계다. 이전 화면에서 부산 전체 시간 분포만 제공하던 제약을 해소해, 지도에서 고른 구·군과 원문 동의 시간 패턴을 직접 탐색한다.

집계는 194개 구·군+원문 읍면동 이름 조합을 포함한다. 194는 부산 행정동 수가 아니다. 기존 연도·처리조건별 원문 지역 2,901행의 유형별 합계와 새 집계를 대조한다. 새 신고나 구버전 분석값을 섞지 않았고 접수번호와 정밀 신고 위치는 공개하지 않는다.

기존의 단일 막대·긴 설명 구조는 지도와 핵심 관측, 지역별 추세·시간 분포, 주민 배경, 기존 대응과 다음 확인 질문 순서로 변경한다. 기본 화면에는 수치를 읽는 데 필요한 공간 단위·기간·처리조건만 짧게 표시하고 상세 해석과 출처는 펼쳐보기로 제공한다.

## 2. 지도에서 보여주는 값

지도는 현재 참고 구·군 윤곽 위에 **신고 원문의 구·군 이름별 접수 건수**를 비례기호와 숫자로 표시한다. 기호는 지역 집계를 가리키는 표시이며 사건 좌표가 아니다. 구·군 선택에 이어 원문 읍면동별 상세 결과를 탐색한다.

5년 각 연말의 공식 구·군 코드와 이름 16쌍은 일치하지만, 경계 자체가 불변인 것은 아니다. [대통령령 제30671호](https://www.law.go.kr/lsInfoP.do?lsiSeq=217917&efYd=20200612)는 2020-06-12 금정구 금사동 62-1·62-13번지를 해운대구로 편입했다. 따라서 현재 경계를 과거 5년의 동일 공간으로 간주한 색칠을 하지 않는다. 선택 지역의 면색은 탐색 강조에만 사용한다.

지도용 960개 연도×조건×구군×종별 셀과 상위 합계를 대조했고, 16개 라벨 기준점은 실제 참고 도형 안의 대표점으로 계산했다. 좁은 구는 연결선으로 이름 위치를 분리한다. 근거는 `data/processed/심층분석-20260915/map_validation.json`과 `district_label_points.json`이다.

## 3. 심층 사례는 왜 이 네 곳인가

최종 위험 순위나 대표 표본을 만들지 않았다. 5년 반복 목록에서 같은 군·같은 분류의 비교, 선택 영향의 차이, 행정동 대응 가능성, 다른 신고 유형이라는 서로 다른 질문을 검토할 네 사례를 골랐다. 기준과 선정 이유는 `case_selection_evidence.csv`에 기록한다. 벌집제거는 사례와 보완 검토에서 제외한다.

아래는 **C조건(정상 처리 중 업무운행·훈련출동·구급차소독 제외), 해당 원문 지역·세부유형, 5년 합계**다. 잔존율의 분모는 같은 조건의 기존 8개 컬럼 완전행이며 부산 전체 신고가 아니다.

| 원문 지역·유형 | 선택17 합계 | 비교용 기본8 합계 | 잔존율 | 선정 질문 |
|---|---:|---:|---:|---|
| 기장군 기장읍 · 구급 질병 | 4,773 | 5,878 | 81.20% | 단일 인구 코드 후보가 있는 같은 군의 비교 기준 |
| 기장군 정관읍 · 구급 질병 | 1,937 | 5,315 | 36.44% | 같은 군·같은 분류의 선택 영향 대조 |
| 연제구 연산동 · 구급 질병 | 7,588 | 13,198 | 57.49% | 반복 질병 분류의 관측 규모가 크지만 복수 행정동인 경우 |

기장읍·정관읍의 질병 합계 비는 비교용 기본8에서는 약 1.11배, 선택17에서는 약 2.46배다. 두 읍의 실제 질병 위험 차이라고 설명할 수 없는 이유가 구체적으로 드러난다. 동시에 두 읍 모두 5년 반복과 2022년 정점이라는 관측을 후속 질문으로 유지할 수 있다.

## 4. 시간 분포에서 새로 확인한 점

C조건에서 네 사례 모두 4시간 구간 중 08~11시 접수가 가장 많았다. 기장읍 질병 1,045건, 정관읍 질병 424건, 연산동 질병 1,640건, 금곡동 시건개방 65건이다. 요일 최다는 질병 세 사례가 월요일, 금곡동 시건개방은 목요일이었다. 이는 집계상 최대 구간이며 통계적으로 유의한 집중이나 개인별 반복 신고를 뜻하지 않는다.

월별 비교에서 달력 일수로 나누면 기장읍 질병은 7월 약 3.06건/일, 정관읍 질병은 6월 약 1.19건/일이 각 사례 내 최대였다. 정관읍은 단순 월 합계로는 3월 183건이 가장 많지만, 6월은 179건/150일로 일수당 값이 더 높다. 따라서 건수와 기간 보정 비교를 함께 제공한다. 공휴일·실제 운영일 보정이나 노출 인구 대비 발생률은 아니다.

![사례별 요일·시간 분포](../../data/processed/심층분석-20260915/figures/02_case_weekday_hour.png)

포함조건을 바꾸면 금곡동 시건개방의 추세 판단도 달라진다. A조건에서 기본8은 2020년 105→2024년 108건인데 선택17은 60→56건이다. B/C에서는 기본8 93→81건, 선택17 55→50건으로 모두 감소한다. 질병 세 사례는 A/B/C 모두 두 연도 사이 감소 방향을 유지했지만 감소 폭은 같지 않다.

시간 구간을 자정 기준 8시간·12시간으로 합치면 네 사례의 C조건 최대 구간은 각각 08~15시·12~23시로 바뀐다. '오전 집중'이라는 짧은 문장을 인력 배치 시간으로 곧바로 바꿀 수 없음을 확인했다. 조건별 수치는 `case_condition_time_sensitivity.json`에 보존한다.

## 5. 주민 배경을 어떻게 활용하는가

전체 연령 인원·비중은 기존 205개 읍면동×5개년 자료를 유지한다. 아래는 2024년 말의 단일 인구 코드 후보에 대한 조건부 배경이다. 신고 대상자의 나이, 환자 수, 실제 행정동 전체 신고를 뜻하지 않는다.

| 주민 배경 후보 | 전체 주민 | 0~14세 | 15~64세 | 65세 이상 | 65세 이상 비중 |
|---|---:|---:|---:|---:|---:|
| 기장읍 | 51,101 | 4,328 | 33,584 | 13,189 | 25.81% |
| 정관읍 | 78,483 | 14,574 | 53,278 | 10,631 | 13.55% |
| 금곡동 | 34,752 | 2,559 | 21,984 | 10,209 | 29.38% |

같은 군의 두 읍도 전체 연령 구성이 다르므로 현재 서비스를 안내할 때 대상 조건과 누구나 이용할 수 있는 경로를 구분해 볼 이유가 있다. 이것만으로 특정 연령층이 서비스를 이용하기 어렵다거나 추가 인력이 필요하다고 결론 내리지는 않는다. 연산동은 여러 행정동에 대응하므로 주민 인구를 하나로 합치지 않는다.

**이번에 구현한 보완:** 지역별 관측과 함께 기존 서비스의 대상·시간·이용 경로를 비교하는 정보카드를 제공한다. 새 시설을 가정하지 않고 기존 안내를 지역 탐색 흐름에 연결했다. 이는 정보 제공 기능의 구현이며 주민 인지도나 피해 감소를 검증한 정책 성과가 아니다.

**다음으로 판단할 보완 후보:** 기장읍·정관읍에서 기존 서비스 안내가 실제로 이해·이용되는지 익명 인지도·미이용 사유와 적격 대상 대비 등록·대기기간을 확인한다. 안내 경로 혼동이나 접근 장벽이 확인되면 그 항목에 맞춘 안내·연계 개선을 검토한다. 현재 건수나 주민 연령 비중만으로 방문 인력 확대를 제안하지 않는다.

**보류:** 연산동의 특정 행정동 보완안은 당시 주소·좌표 정의·경계 결합을 확인한 후 판단한다. 금곡동 시건개방은 접수 목적과 인명위험·현장 결과의 비식별 교차표를 먼저 확인한다. 시건개방을 고독사·독거노인·단순 비긴급 신고로 치환하지 않는다.

## 7. 재현과 검증

기존 분석 입력 명세와 최종 집계의 해시를 재사용했다. 추가 분석 작성자와 별도의 검증자가 새 집계·사례·서비스 근거를 대조한다. 웹은 실제 브라우저에서 지도 기호의 합계, 선택 지역과 원문 동 상세, 필터·빈 상태·확대축소·모바일 표시를 확인한다. 개별 검증 결과와 화면은 같은 심층분석 출력 폴더에 기록한다.

```powershell
$env:PYTHONIOENCODING = 'utf-8'
.venv-check/Scripts/python.exe analysis/00_공통/build_deep_analysis_20260915.py
.venv-check/Scripts/python.exe analysis/00_공통/report_deep_analysis_20260915.py
```

서비스 근거 재수집은 `collect_deep_services_20260915.py`를 별도로 실행한다. 이 작업은 현재 페이지를 다시 받아오기 때문에 조회시각·내용·해시가 달라질 수 있다. 이미 확보한 공식 스냅샷은 분석 재현을 위해 다시 수집할 필요가 없다. 의존성은 기존 `requirements-final-20260915.txt`를 사용한다.

## 8. 실제 완료한 검증과 결과 열기

심층 데이터 독립 검사 126개, 웹·보고서 독립 검사 183개, 이후 월별·사례시간·주민 요약 변경분 독립 검사 148개가 통과했다. 브라우저에서는 90개 필터 조합의 지도 16개 기호(1,440개 값), 111개 지역 선택 상태의 열지도 42셀, 90개 조건의 월별 12칸, 12개 사례·처리조건의 세부분류 6시간 구간을 대조했다. 16개 구·군 키보드 선택, 빈 검색, 확대·초기화, 인구 후보 연결, 360·390px 가로 넘침, 파일 직접 실행과 HTTP 실행을 확인했다. 검증한 실행에서 JavaScript 오류는 발생하지 않았다.

- 독립 검증: `independent_deep_verification.json`, `independent_deep_ui_report_review.json`, `independent_deep_ui_delta_review.json`
- 브라우저 검증: `browser_verification/result.json`, `browser_verification/details_result.json`
- 최종 웹 파일·ZIP 내용 해시: `browser_verification/delivery.json`
- 원본 대비 그림 입력·출력·코드 해시: `figure_manifest.json`

위 상대 경로는 `data/processed/심층분석-20260915/` 기준이다. 이전 최종 집계와 검증은 보존하고, 새 버전의 검증과 섞어 완료 범위를 표현하지 않는다. 정책 공백·인과관계·개별 연령별 사고는 기술 검증 통과와 별개로 확정하지 않는다.

현재 웹은 `web/final/index.html`을 직접 열면 된다. `output/부산119-지도심층분석-20260915.zip`은 최종 웹 폴더 11개 파일만 포함하며 압축 무결성과 각 파일의 해시를 확인했다. 압축을 풀고 `index.html`을 열면 추가 설치 없이 실행된다.
