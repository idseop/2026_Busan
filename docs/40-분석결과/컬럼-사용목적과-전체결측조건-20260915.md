# 컬럼 사용 목적과 전체 결측 제외 조건

대상: 지정 2020~2024년 신고접수 CSV 5개. 기존의 ‘기본 8개·보조 15개’는 분석 중요도 순위가 아니라 당시 집계에 필요한 값과 추가 검증용 값을 나눈 구현 구분이었다. ‘보조’라는 이유로 최종 분석에서 사용하지 않는다는 뜻으로 사용해서는 안 된다.

**최종 적용:** 사용자가 ‘분석에 사용할 컬럼을 뽑고 필요한 컬럼의 결측값은 모두 제외’하도록 진행을 요청했다. 아래 **17개를 하나의 분석표로 사용**한다. 기본·보조로 나누어 일부 컬럼의 결측을 허용하지 않는다.

접수경로는 경로별 분포, 좌표는 숫자·범위·두 좌표 기록 일치 점검, 현장지역은 재난지역과 교차 검증, 관할기관은 기록된 소방서·센터별 분포에 사용한다. 좌표의 공식 의미·좌표계·정확도 검증을 통과하기 전에는 점을 실제 행정동에 배정하지 않는다. 현재 결정할 질문이 없는 여부 항목 6개는 원본에 보존하고 이번 17개 분석표에서는 제외한다. 전부 빈 중앙요청 컬럼도 여기에 포함된다.

## 설명서 전체 확인과 이번에 제외한 항목

`data/부산소방재난본부_119신고접수_현황_컬럼_정보_데이터.xlsx`의 `column_info!B3:F40`에는 38개 컬럼 설명이 있다. 영어 이름뿐 아니라 E열 한글명과 F열 상세 설명을 직접 확인했다. 선택한 17개 외의 21개도 확인했으며 누락해서 제외한 것이 아니다.

현재 지정 원본 5개의 CSV 헤더를 읽어 설명서 영문명의 대소문자만 정규화해 대조한 결과, 모두 같은 38개 컬럼 집합이었다. `codebook_all38_selection.csv`에 설명서 시트·행·B/E/F 셀 주소, 원문 이름·설명, 최종 선택 여부와 사용·제외 이유를 기록했다. `codebook_audit.json`에는 현재 XLSX·코드·출력 해시와 38=17+21 검산을 기록했다. 원본 설명서를 수정하지 않았다.

- **신고 시간의 중복 표현 10개:** `DCLR_YMD`, `DCLR_TM`, `DCLR_YR`, `DCLR_MM`, `DCLR_DAY`, `DCLR_HR`, `DCLR_MN`, `DCLR_DOW`, `SEASN_NM`, `QTR_NO`. 필요한 연도·월·요일·시간대 등은 검증한 `DCLR_DT`에서 파생하므로 시간 분석을 버린 것이 아니다.
- **접수 종료 관련 3개:** `RCPT_END_DT`, `RCPT_END_YMD`, `RCPT_END_TM`. 접수 종료 시점이며 현장 도착 시간이 아니므로 현장 대응시간으로 사용하지 않는다. 기존 품질 검사는 보존한다.
- **도시농촌구분명·긴급구조규모명 2개:** `CTY_FRMVL_SE_NM`, `EMRG_RSCU_SCL_NM`. 현재의 동·유형·시간·주민 배경 비교에 별도 활용 질문이 없어 제외했다. 특히 규모명 상세 설명이 출동 횟수라고 적혀 있어도 접수행을 출동수로 전환하지 않는다.
- **아래 여부 항목 6개:** 현재 결정할 질문이 없거나 관측 정보가 없는 항목으로 이번 분석표에서는 제외하고 원본에 보존했다.

| 컬럼 | 의미 | 실제 활용할 질문·사용 조건 |
|---|---|---|
| OTR_CTPV_DCLR_YN | 타시도신고여부 | 같은 내용의 다른 시도본부 신고 여부. Y를 부산 밖 사건으로 판단하지 않음 |
| OTR_CTPV_DSPT_YN | 타시도출동여부 | 다른 시도의 출동 기록 비교가 필요한 경우 사용 |
| CLLBC_YN | 콜백여부 | 콜백 기록 여부. 빈칸을 N으로 바꿀 근거 없음 |
| JNT_CRSP_YN | 공동대응여부 | 공동대응 기록 여부. 대응 공백을 직접 나타내지 않음 |
| CENTR_RSUN_DSPT_DMND_YN | 중앙구조대출동요청여부 | 지정 5년 자료에서 전부 비어 있어 관측된 비교 정보가 없음 |
| CHEM_ACDNT_YN | 화학사고여부 | 해당 질문이 선정될 때 사용. 현재 미리 화학사고 분석으로 범위를 좁히지 않음 |

최종 사용 컬럼에서는 필수·보조를 나누어 결측을 허용하지 않는다는 사용자 요청을 적용한다. 다만 어떤 컬럼을 쓸지는 실제 질문·정의·연도별 기록 상태로 판단해야 한다. N은 값이며 결측이 아니다. 빈 문자열과 공백은 결측이고, 공란을 N으로 채우지 않는다. 결측이 없다는 사실만으로 좌표나 동 배정이 정확해지는 것은 아니다.

## 실행한 전체 결측 제외 비교

부산 명시 접수 중 각 조건의 모든 컬럼이 비어 있지 않은 행을 계산했다. 원본을 지우지 않고 전처리본·제외 기록을 별도로 저장했다. 조건 비교를 먼저 실행한 뒤 사용자 진행 요청에 맞춰 17개 조건을 현재 분석 기준으로 채택했다. 결측 여부에 따른 동일한 행집합을 사용하며 결과에 맞춰 다시 행을 고르지 않는다.

| 연도 | 기존 8개 | 9개: 8개+접수경로 | 17개: 9개+좌표4+현장지역2+관할기관2 | 22개: 23개 중 중앙요청 제외 | 기존 23개 전부 |
|---|---:|---:|---:|---:|---:|
| 2020 | 231,726 | 231,726 | 114,236 | 0 | 0 |
| 2021 | 257,495 | 257,495 | 139,189 | 0 | 0 |
| 2022 | 291,566 | 291,566 | 158,478 | 0 | 0 |
| 2023 | 282,414 | 282,414 | 149,390 | 179 | 0 |
| 2024 | 271,313 | 271,313 | 143,396 | 158 | 0 |
| 합계 | 1,334,514 | 1,334,514 | 704,689 | 337 | 0 |

23개 조건은 전부 빈 중앙요청 컬럼 때문에 남는 행이 없다. 중앙요청만 빼도 22개 조건은 2020~2022년 행이 없어 5년 비교에 사용할 수 없다. 일부 여부 컬럼에는 Y·N·공란이 섞여 있으며 연도별 기록 양상도 달라, 단순히 ‘Y 사례만 남는다’고 설명해서도 안 된다.

채택한 17개 조건은 기존 8개 완전행의 약 52.81%만 남는다. 따라서 남은 부분집합을 분석하며 이를 그대로 부산 신고 전체의 특성으로 일반화하지 않는다. 추가 컬럼이 요구하는 결측 제외로 어느 연도·유형·동이 줄었는지도 함께 기록한다.

이번 17개 비교에서 원문 구군·동명 조합 자체가 완전히 사라지는 경우는 없었다. 그러나 추가로 제외된 접수는 629,825행이며, 종별 잔존율은 구급 약 57.70%, 구조 44.64%, 화재 41.52%, 기타 33.79%로 다르다. **동 이름이 모두 남아도 신고 유형 구성은 달라진다.** 이 결과는 인구자료의 205개 행정동별 신고가 모두 연결됐다는 뜻도 아니다.

기존 8개 완전행에서 현장시군구명 결측은 470,415행, 사고발생경도 결측은 275,171행이다. 한 접수에 여러 결측이 함께 있을 수 있어 이 숫자들은 합산하지 않는다. 다음 분석은 17개 완전행의 시간·유형·원문 동별 반복성과 위치·지역·관할 기록의 품질을 함께 살펴본다.

## 코드·입력·출력 연결

- 실행 코드: `analysis/00_공통/complete_all_selected_20260915.py`
- 지정 원본 명세: `data/interim/분석입력-2020-2024/manifest.json`
- 재사용 전처리·해시 근거: `data/processed/컬럼선별-결측제외-20260915/`
- 이번 비교 결과: `data/processed/동대응-전체결측제외-20260915/completeness/`
- 조건별 집계: `stage_completeness.csv`
- 컬럼별 결측: `selected_column_missing.csv`
- 기존 보조 15개별 목적·결측·실제 값: `optional_column_use_and_missing.csv`
- 설명서 전체 38개 대조·선택·제외 근거: `codebook_all38_selection.csv`, `codebook_audit.json` (실행 코드 `analysis/00_공통/audit_codebook_selection_20260915.py`)
- 실제 범주·여부 값: `observed_categorical_and_flag_values.csv`
- 동별 잔존: `original_region_totals_retention.csv`
- 17개 비교 전처리본과 제외행: `complete_17_YYYY.csv.gz`, `excluded_core8_to_17_YYYY.csv.gz`

원문 동명의 공식 동 대응 검증은 컬럼 수 선택과 독립적으로 계속 진행한다. 단일 행정동 대응과 여러 행정동 대응을 구분하고, 여러 동에 걸친 원문명을 인구 비례 등으로 강제 배정하지 않는다.

실행한 공식 동 대응 검증은 [원문 동·행정동 대응 검증](원문동-행정동-대응검증-20260915.md)을 따른다. 이름·코드에 따른 조건부 인구 배경과 검증된 실제 신고 위치를 구분한다.
