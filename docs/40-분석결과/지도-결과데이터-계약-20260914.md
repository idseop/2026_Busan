# 부산 동 지도용 분석 결과 계약

최초 작성 2026-09-14, 웹 실행 범위 갱신 2026-09-15. 대상 신고·주민 배경은 2020~2024년이다. 사용자 후속 요청으로 `web/final/`에 실제 웹을 구현한다. 기존 웹의 과거 집계는 사용하지 않는다.

현재 구현 데이터는 `dashboard-data.js`의 `BUSAN_DATA`와 `map-data.js`의 `BUSAN_MAP`이다. 연도·처리조건·종별을 지원하는 집계만 연동한다. 원문 지역 필터는 지역 상세에 적용하며 부산 관측집합 시간 분포를 동별 시간으로 바꾸지 않는다. 인구에는 신고 처리조건·종별을 적용하지 않고, 5개년 신고 전체 선택 시에도 인구는 명시된 단일 연말 기준을 사용한다. 공식 대응 서비스는 출처·시점·대상·운영 조건·보류 이유를 별도 개체로 제공한다.

## 2026-09-15 분석표·후보 대응 갱신

완전행 적합성 평가 후 `analysis_use_scope: descriptive_complete17_only`, `population_generalization_status: unsupported`, `final_area_prioritization_status: held`를 적용한다. 이 상태는 17개 데이터의 오류나 폐기를 뜻하지 않고 전체 지역 비교로의 일반화 범위를 제한한다. 원문 동별 표시에는 제외 전후 건수·잔존율·반복 조건 변화·끝 연도 증감 반전 여부를 진단 근거로 연결한다. 높은 순위상관만으로 우선순위 상태를 승인하지 않는다.

현재 신고 분석표는 선택한 17개 원본 컬럼의 결측을 모두 제외한 704,689행이다. 지도 데이터에는 `analysis_dataset_id: complete17_20260915`, 선택 컬럼 목록, 지역·처리 포함조건, 연도별 원본/제외/잔존 건수와 제외 이유를 함께 연결한다. 기존 8개 기준 집계를 같은 모집단처럼 혼합하지 않는다.

공식 관계표로 얻은 후보 코드는 `candidate_admin_dong_codes`, `name_match_status`, `code_period_status`로 보존한다. 단일 코드의 인구 배경을 붙인 원문명칭 표는 `conditional_population_background`이며 `receipt_geography_confirmed: false`를 유지한다. 이것을 검증된 `receipt_metrics`나 행정동 전체 신고로 승격하지 않는다. 모든 연령 인원·비중과 연말 기준일을 유지한다.

17개 원본 컬럼의 결측 0과 파생된 지리 연결의 미확인은 별개다. 다중 후보·연도 불일치 때문에 생긴 연결 상태를 지우거나 가짜 코드로 채우지 않는다. 해당 상태는 지도에서 설명할 품질 정보이며, 행정동의 신고 0건으로 표현하지 않는다.

## 개체와 연결 키

| 개체 | 키 | 필수 내용 |
|---|---|---|
| geography | 연도 + 행정동 코드 + 경계 버전 | 구군 코드·이름, 동 이름, 코드 체계, 유효 시작·종료일, 경계 기준일, 공식 원본·해시, 연결 검증 상태 |
| receipt_metrics | 연도 + 검증된 공간 키 + 포함조건 + 종별 + 분류 + 시간차원 | 접수행수, 분모와 구성비, 달력 일수·일평균, 원본 집계 경로, 연결률, 미연결 사유 |
| population_background | 연도 + MOIS 행정동 코드 | 12월 말 기준일, 총인구, 0~99세·100세 이상 전체 인원과 비중, 보조 연령구간, 구군 소속, 원본 경로·해시 |
| response_evidence | 대응 근거 ID | 분야, 시설·서비스명, 위치, 대상, 운영 시간, 이용 조건, 운영 범위, 기준일, 공식 출처, 확인일, 미확인 항목 |
| review_candidate | 후보 ID | 동·유형, 반복 연도, 구성·시간 특성, A/B/C 민감도, 공간 신뢰도, 선택·보류 이유, 필요한 질문, 근거 ID 목록 |
| proposal_candidate | 보완 후보 ID | 신고 근거 → 주민·현장 배경 → 기존 대응 → 확인된 필요성 → 검토안, 미확인 조건, 확인 전 허용되지 않는 해석 |

행정동 코드와 통계청 경계 코드는 별도 필드다. 문자열 앞자리를 바꾸는 방식으로 변환하지 않는다. 연도별 행정동 수가 같아도 코드·경계 변화 여부를 확인한다. 원문 재난읍면동은 `raw_region_label`에만 보존하며 검증된 `admin_dong_code`를 대신하지 않는다.

## 값과 상태

- 실제 관측·검증한 0건만 `0`으로 표시한다. 연결 미완료·자료 미확보·확인하지 않은 운영 조건은 `null`과 사유를 함께 제공한다.
- 동별 신고 연결이 보류된 현재 상태는 `receipt_metrics: null`, `linkage_status: not_validated`이다. 인구가 확보된 동을 신고 0건 동으로 칠하지 않는다.
- 공간 상태는 `validated`, `not_validated`, `coordinate_missing`, `outside_verified_boundary`, `multiple_matches`, `boundary_ambiguous`, `code_period_unresolved`를 구분한다. 실제 검사를 하지 않은 항목에 실패 상태를 만들어 넣지 않는다.
- 결과의 지식 상태는 `observed`(관측 사실), `interpretation`(해석), `hypothesis`(검토 가설), `unverified`(미확인)로 구분한다.
- 후보별 미확인 서비스 범위를 ‘없음’으로 표시하지 않는다. 대응 공백이 확인되지 않았으면 `gap_status: unverified`로 유지한다.
- 사용자 지정으로 벌집제거는 집중 검토·추가 조사·제안에서 제외한다. 전체 접수 검산에는 남기되 후보 상태는 `excluded_user_scope`로 구분한다. 다른 유형도 반복성만으로 자동 추천하지 않는다.

## 집계·필터 검증

1. 부산 전체 값은 ‘재난시도 부산 명시 접수’라는 모집단을 표시하고 지역 미기재 규모를 함께 노출한다. 행정동 필터에서 빠진 미연결 접수는 전체에서 사라지지 않는다.
2. A 전체 처리, B 정상, C 정상 중 명시적 운영성 분류 제외의 정의를 표시한다. 기본 접수 현황은 A, 비교 검토는 B·C를 함께 확인한다. 필터가 바뀌면 구성비 분모도 함께 바뀐다.
3. 서로 다른 집계표를 이어 붙여 접수 건수를 더하지 않는다. 월·시간·요일 표는 같은 원본의 다른 주변합계다. 월×시간 필터는 실제 결합 집계가 있을 때만 제공한다.
4. 동 합계 + 동일 조건의 미연결 합계 = 부산 명시 합계인지 검사한다. 원문 읍면동 집계를 행정동 합계로 사용하지 않는다.
5. 연도 필터는 같은 해 12월 말 인구를 배경으로 연결한다. 연간 신고와 인구의 관측 시점이 완전히 같지 않음을 표시한다. 5년 인구를 더해 주민 수로 표시하지 않는다.
6. 개인 접수번호·정밀 위치·원본 행 기록은 지도 배포 파일에 포함하지 않는다. 내부 추적 파일과 공개 집계를 구분한다.

## 현재 제공 범위와 후속 승인 조건

이번 분석의 신고 유형·시간 집계와 인구 연령표는 각각 제공할 수 있다. 동별 접수·주민 배경의 연결 프로필 및 예방안을 지도에 제공하려면 2020~2024년 각각의 위치·경계·코드 대응을 먼저 검증해야 한다. 기존 대응의 위치·운영 조건·시점을 확인한 근거가 생긴 뒤 대응과 보완 후보를 추가한다. 구조만 맞추기 위해 가짜 시설·효과 수치·정책 제안을 채우지 않는다.
