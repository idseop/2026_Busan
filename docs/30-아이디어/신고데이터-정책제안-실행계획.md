# 부산 신고 데이터를 활용한 지역 맞춤 정책제안

> 현행 주제 · 2026-09-13 사용자 결정. 주제는 확정했으며 데이터 확보와 분석 결과는 미검증이다.

## 질문과 두 분석 축

**부산의 신고는 어디에, 언제, 어떤 유형으로 집중되며, 지역의 연령 구성과 상권 특성을 함께 고려하면 어떤 정책을 어느 지역·시기에 우선 검토해야 하는가?**

| 분석 축 | 분석 흐름 | 산출물 | 해석 범위 |
|---|---|---|---|
| 1. 시공간 신고 특성 × 동별 연령 구성 | 신고 위경도 검증 → 행정동 배정 → 발생일시로 시간대·요일·월·계절 비교 → 동일 지역·기간의 연령 구성과 연결 | 동별 신고 지도, 시간대·계절 비교, 연령 구성과 신고 특성 비교표 | 지역 특성의 관계. 신고자의 나이나 피해자·환자 연령을 알아낸 것이 아님 |
| 2. 상권 특성 × 신고 특성 | 점포 위치·업종·기준시점 검증 → 행정동별 상권 구성 → 신고 유형·시간 패턴과 비교 | 업종 구성별 신고 비교, 상권별 정책 검토표 | 특정 상권에서 관측된 신고 특성. 개별 업소가 신고 원인이라는 의미가 아님 |

위경도는 **위치와 행정동**을 정하고, 시간·계절은 **발생일시**에서 구한다. 두 축은 같은 신고자료와 행정동 기준표를 사용한다. 아동·노인은 지역 연령 구성의 일부로 비교하며 필수 대상에 고정하지 않는다.

## 분석·정책 흐름

부산 전역 자료 확보·검증 → 동별·유형별 시간 패턴 → 연령 구성 및 상권 구성과 각각 비교 → 함께 나타나는 특성·예외 지역 확인 → 정책 후보와 실행 조건 → 지도·보고서.

주 사용자는 분석한 사건 유형에 해당하는 부산시·구군 정책 담당자다. 담당 부서와 실제 업무 근거는 정책별로 확인한다. 결과표는 `지역 / 유형 / 집중 시기 / 연령 구성 / 상권 특성 / 근거 / 정책 후보 / 담당 업무 / 추가 확인 / 평가 지표`로 정리한다.

- 정책의 대상·장소·시기·활동을 구체화하되 실제 결과가 나오기 전에 지역명·효과 수치를 채우지 않는다.
- 예: 특정 유형의 신고가 특정 상권·시간대에 반복되는지 확인한 뒤 그 유형에 맞는 점검·안내·지원 시간 조정을 검토한다. 이는 제안 예시이며 관측 결과가 아니다.
- 인력 배치·동선·미래 예측은 필수 산출물이 아니다. 정책 집행에 필요한 자료와 요청이 있을 때 별도 확장한다.

기존 조사 기록의 출발점(이번 구조 변경에서 재실사하지 않음):

- 112 경찰서별 연간 통계는 동별·시간대별·유형별 분석의 핵심 자료로 바로 사용할 수 없다. [출처: 부산광역시경찰청, 2025년 기준, https://www.data.go.kr/data/15067163/fileData.do]
- 부산 구급출동 상품은 전체 원본과 위경도·발생일시·유형 컬럼을 직접 확인해야 한다. 현재 원본 확보 증거가 없다. [출처: 부산소방재난본부, 기존 2026-09-08 확인 기록, https://bigdata-119.kr/goods/goodsInfo?goods_mng_sn=390]
- 부산 오픈랩에 필요한 신고자료가 있는지는 미확인이다. 제공을 전제하지 않는다. [출처: 부산 빅데이터 혁신센터, https://busanbigdata.kr/]

## 계산·해석 규칙

1. 부산 전역을 같은 기준으로 비교한다. 일부 구 자료로 전역 순위를 만들지 않는다. 경찰서 관할을 행정구·행정동으로 간주하지 않는다.
2. 신고·출동·확인 사고는 별도 지표다. 다중 신고·다중 출동을 식별할 근거가 없으면 임의로 같은 사건으로 합치지 않는다.
3. 시공간 결합의 기본 키는 `행정동 코드 × 기준기간`이다. 사건자료는 원래 입도를 보존하고 동별 집계표와 구분한다. 경계 위·부산 밖·매칭 실패 좌표는 별도 집계하고 임의 배정하지 않는다.
4. 계절 월 구분, 겨울의 연도 귀속, 시간대 구간, 관측일 수와 누락 기간을 기록한다. 완전한 연간 주기가 없으면 계절성으로 일반화하지 않고 관측기간의 월별 차이로 표현한다. 한 해의 패턴을 반복적 계절성으로 확정하지 않는다.
5. 연령별 인구는 지역 설명변수다. 전체 신고 × 연령 인구비율로 연령별 신고를 만들지 않는다. 전체 신고 / 노인 인구를 노인 신고율로 부르지 않는다. 실제 연령 구간이 아동·고령 기준과 다르면 구간을 임의 분할하지 않는다.
6. 업무 수요 건수와 규모 보정 지표를 함께 보되, 분모는 목적에 맞게 선택한다. 전체 인구·유동인구·점포수는 서로 다른 노출량이다. 전체 신고 / 음식점 수를 음식점 사고율로 해석하지 않는다.
7. 상권 축은 먼저 동별 점포수·업종 비중과 신고 유형·시간의 관계를 비교한다. 점포 인접 신고를 해당 점포 사건으로 단정하지 않는다. 상권 경계 단위를 추가하면 동별 분석과 별도로 표시하고 중복 매칭을 검증한다.
8. 인구 규모·상권 규모·관측기간 등 대안 설명을 함께 검토한다. 지역 간 상관은 인과관계나 개인별 위험의 증거가 아니다. 임의 가중치 종합지수 대신 지표별 비교를 기본으로 한다.
9. 결측을 0으로 바꾸지 않는다. 원본과 집계 건수의 일치, 제외 건수, 결합 전후 행 수를 기록한다. 임계값·시간구간·상권 분류를 바꾸었을 때 결과가 유지되는지 확인한다.
10. 공개 지도는 집계 결과를 기본으로 한다. 사건별 좌표·원시 신고 내용·개인정보를 Git과 웹에 올리지 않으며 공개 조건과 소수 건수 처리를 확인한다.

| 단계 | 폴더 | 완료 기준 |
|---|---|---|
| 공통 | `analysis/00_공통/` | 원본 카탈로그, 경계·시간 기준, 결합·제외 기록 |
| 신고 시공간 | `analysis/01_신고시공간/` | 동·유형·시간별 집계와 원본 대조, 기간 누락 표시 |
| 연령 연계 | `analysis/02_연령연계/` | 동별 연령 구성 비교, 개인 연령 추정 없는 해석 |
| 상권 연계 | `analysis/03_상권연계/` | 상권 기준시점·업종 구성 비교, 교란·예외 검토 |
| 정책 제안 | `analysis/04_정책제안/` | 결과 → 정책 → 담당 업무 → 집행 조건 → 평가 지표 연결 |

지도는 **부산 전체 → 유형·시기 필터 → 동 상세(연령·상권·불확실성) → 정책 근거** 순서로 읽는다. 연령·상권 레이어는 실제 제공 범위에서만 켠다. 기대효과는 정책 검토 근거와 대상 지역·시기 구체화이며, 신고 감소 등 효과는 시행 전후 비교·비교집단 등 별도 평가 설계가 있어야 검증할 수 있다.

## 단일 웹페이지의 정책 검토 흐름

부산 전체 행정동 지도에서 **동 클릭 → 신고 유형·시간·계절 → 동별 연령 구성 → 상권·현장 특성 → 정책 후보와 근거**를 한 페이지 안에서 확인한다. 상세 화면·가설·표시 기준은 `web/README.md`를 따른다.

사용자가 제시한 연결 사례는 구급·고령인구와 안부 확인/고립 예방/노인일자리 연계, 구조·아동인구와 어린이 안전, 건설현장 주변 화재와 예방시설·장비, 주점 상권의 구조·구급과 취약시간대 예방활동·순찰이다. 모두 **검증할 정책 가설**이며 관측 결과나 확정 권고가 아니다. 대상·사건 세부 유형·기존 자원·업무 근거가 연결되지 않으면 정책 확정을 보류한다.

신고가 많다는 이유로 특정 연령 인구가 많다고 추론하지 않는다. 신고와 인구를 각각 측정한다. 노인일자리는 적합한 지원 활동과 사업 조건을 확인한 뒤 연계하는 실행 방안이며 구급 수요에서 직접 도출하지 않는다. 건설현장은 상가 업종과 별도 자료로 위치·공사기간을 확인한다.

**신규 실사 단서:** 사용자가 부산소방재난본부 신고 접수 현황 엑셀의 위경도 존재를 설명했다. 이번에는 파일·공식 출처를 직접 확인하지 않았으므로 사용자 제공 단서로 기록한다. 실제 위치의 의미, 발생/접수 시각, 구급·구조·화재 유형, 전역·기간 포함 여부를 우선 실사한다. 기존 구급출동 상품과 동일 자료라고 가정하지 않는다.

## 현재 작업

- 주제·두 분석 축 확정, 데이터 실사 전. 확정 주제와 분석 가능 판정은 구분한다.
- 이번 변경은 하네스 정비다. 데이터 다운로드·분석 완료를 의미하지 않는다.
- 관광 숏리스트와 기존 예방지원·119 예측 문서는 검토 이력으로 보존한다. 현행 기준은 이 문서다.
