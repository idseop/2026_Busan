# 부산 신고 기반 예방·지원활동 지도 서비스 — 고도화 프롬프트

> 팀 공유용 기획 지시문 · 2026-09-08
> 상태: 주제 검토 단계. 핵심 신고 원본의 대상·유형·위치·시간 변수 확보 여부에 따라 구현 범위를 결정한다.

## 한눈에 보는 주제

| 항목 | 핵심 내용 |
|---|---|
| 주제 | 부산시 신고 특성에 따른 예방·지원활동 우선지역 선정 및 인력 배치 |
| 문제제기 | 신고 대상과 사건 유형에 따라 필요한 활동이 다르다. 부산의 어디에 어떤 활동을 보완할지 분석한다. |
| 분석 흐름 | 부산 전체 현황 → 지역별 비교 → 기존 지원과 대조 → 우선지역 선정 → 인력·활동 배치 → 가능한 경우 동선 제안 |
| 대상 | 노인·아동 등 원본에서 식별 가능한 지원 대상. 신고자의 나이와 피해자·환자·지원 대상의 나이를 구분한다. |
| 데이터 | 부산 전역을 포괄하는 원본 신고자료 또는 공식 집계. 대상 연령·사건 유형·발생 위치·시간의 실제 제공 범위를 확인한다. |
| 활동 | 아동 안전활동, 노인 안부 확인·생활위기 지원 등. 사건 유형과 기관의 실제 업무에 맞춰 제안한다. |
| 인력 | 경찰·복지 담당자·보건소·안부 확인 활동 인력 등. 노인일자리 참여자 활용은 선택 가능한 방안이다. |
| 지도 웹페이지 | 부산 전체 신고 분포, 가능한 필터, 우선지역과 선정 근거, 배치안 비교를 제공한다. 세부 위치자료가 있을 때 동선을 표시한다. |
| 기대효과 | 활동 배치의 근거 마련, 지원 공백 검토, 동일 인력·시간 조건에서 활동 범위와 이동 부담 비교 |
| 데이터 원칙 | 샘플·합성자료 제외. 없는 변수 추정이나 임의 결합으로 가짜 사건·연령·좌표를 만들지 않는다. |

## 복사해서 사용할 프롬프트

아래 기획을 부산 DX Challenge Track 1의 분석·시각화 제안으로 고도화하라. 대화를 모르는 팀원도 이해할 수 있도록 중복과 흩어진 내용을 정리하고, 문제제기부터 데이터·분석·서비스·기대효과까지 흐름을 연결하라. 긴 설명을 늘리지 말고 핵심 표와 구체적인 판단 기준으로 품질을 높여라.

**주제:** 부산시 신고 특성에 따른 예방·지원활동 우선지역 선정 및 인력 배치 지도 서비스.

### 반드시 지킬 방향

1. **부산 전체에서 시작한다.** 특정 구·동을 먼저 선택하지 않는다. 부산 전역을 동일 기준으로 비교한 결과로 보완 우선지역을 선정한다. 일부 구 자료만 확보했으면 부산 전체 분석이 가능하다고 쓰지 않는다.
2. **원본·공식 통계를 확보한다.** 공공데이터포털·부산시·부산 오픈랩 등에서 부산 자료를 확인한다. 전국 자료는 부산 기록을 실제로 추출할 수 있을 때만 사용한다. 샘플을 원본 대신 사용하지 않는다. 전체 행 수, 결측·중복, 부산 전역 포함 여부, 기간 누락, 좌표·지역코드 유효성을 검사하고 확보 상태와 함께 기록한다.
3. **없는 데이터를 만들지 않는다.** 신고자 연령을 지원 대상 연령으로 바꾸거나, 노인 인구비율로 노인 신고 건수를 추정하거나, 구별 건수를 임의 좌표에 배분하지 않는다. 서로 따로 집계된 연령·유형·시간 분포를 실제 교차집계처럼 결합하지 않는다. 검증된 지역코드·기간으로 실제 집계를 비교할 때는 연결 기준을 명시한다.
4. **신고 유형과 활동을 연결한다.** 노인 관련 신고 전체를 고독사 위험으로, 모든 아동 사건을 거리 순찰 대상으로 취급하지 않는다. 신고 내용과 공식 업무 근거에 맞는 예방·지원 활동을 제안한다. 과거 신고 기반 활동 계획이며 실시간 긴급출동을 대체하지 않는다.
5. **배치가 먼저, 동선은 다음이다.** 어디에 어떤 활동·인력이 필요한지 결정한 뒤, 위치자료가 충분할 때 방문·순찰 동선을 설계한다. 주 사용 담당자와 실제 조정 가능한 인력·시간·활동 범위를 명확히 하며, 여러 기관의 인력을 자유롭게 재배치할 수 있다고 가정하지 않는다. 인력 자료가 없으면 가정을 명시한 시나리오를 비교하고 현행 배치보다 우수하다고 단정하지 않는다.
6. **공백과 효과를 미리 단정하지 않는다.** 신고가 적다고 안전하다고 보지 않는다. 기존 지원 자료가 없으면 미지원 지역을 확정하지 않는다. 기대효과와 실제 검증 결과를 구분한다.

### 고도화할 내용과 산출물

| 순서 | 할 일 | 산출물 |
|---|---|---|
| 1 | 부산의 문제 배경을 공식 근거로 설명하고 분석 질문을 하나로 정리 | 문제제기·핵심 질문·판단할 결정 |
| 2 | 부산 전역 원본의 제공 범위와 변수 의미를 직접 확인 | 출처·기준기간·공간단위·컬럼·확보 상태·품질 검증표 |
| 3 | 건수·분모·반복 신고·시기 차이와 기존 지원을 고려한 비교 설계 | 우선지역 선정 기준과 가능한 분석 범위 |
| 4 | 신고 유형에 적합한 활동·담당 인력을 근거와 함께 연결 | 유형 → 활동 → 인력 → 배치 조건 표 |
| 5 | 전체 지도에서 선정 지역의 근거와 배치안으로 내려가는 화면 설계 | 부산 전체 지도 → 필터 → 지역 상세 → 배치안 비교 → 조건부 동선 |
| 6 | 동일 조건에서 배치안을 비교할 평가 기준 설정 | 활동 범위·이동시간·담당 부담 등 계산 가능한 지표 |
| 7 | 기존 우수작과 동일한 부분과 달라지는 결정을 구분 | 기존 위험도·순찰 경로 분석 대비 차별성 표 |

최종 응답은 **주제 요약표, 문제→분석→지도 서비스 흐름, 데이터 확보표, 기대효과·검증표, 우선 실행할 작업** 순으로 간결하게 작성하라. 데이터가 부족하면 어떤 분석까지 가능한지와 어떤 원본이 추가로 필요한지를 명확히 제시하라. 기능·알고리즘 이름만 늘리거나 확인되지 않은 효과 수치를 제시하지 마라.

## 현재 확인된 출발점

- **부산 전체 112 신고 원본 통계:** 경찰서별·연도별 집계다. 대상 연령·사건 유형·동별 위치·시간대가 없어 대상별 동선 분석의 핵심 자료로 바로 사용할 수 없다. [출처: 부산광역시경찰청, 2025년 기준, 공공데이터포털](https://www.data.go.kr/data/15067163/fileData.do)
- **부산 구급출동 자료:** 공개 상품과 컬럼표 확인 단계다. 원본 전체는 미확보이며, 현재 확인한 컬럼표에서 대상 연령과 상세 좌표를 확인하지 못했다. 소개문의 AI 설명을 실제 컬럼의 증거로 쓰지 않는다. [출처: 부산소방재난본부, 2026-09-08 확인, 소방안전 빅데이터 플랫폼](https://bigdata-119.kr/goods/goodsInfo?goods_mng_sn=390)
- **부산 오픈랩:** 필요한 신고자료를 제공받을 수 있는지는 미확인이다. 제공 가능하다고 전제하지 않는다.
- **기존 수상작:** KCU 사례는 위험지역 분석·순찰 경로·모니터링을 다룬다. 본 제안은 대상별 사건에 맞는 활동과 인력 배치에서 차별성을 검증한다. 대상을 바꾸는 것만으로 독창성을 주장하지 않는다. [출처: DX Challenge, 2024년 우수작 소개](https://www.dxchallenge.co.kr/s-projects-side-by-side)
