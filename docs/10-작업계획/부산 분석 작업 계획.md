# 부산 분석 작업 계획

작성일: 2026-09-14 · 데이터 점검 근거: 2026-09-13 기록 · 대상 기간: 2020~2024년 · 현재 단계: 데이터 점검 및 분석 설계

> 공유 범위: 이 페이지는 분석 계획 문서다. CSV·PDF·검증 기록 등 로컬 자료는 이번 커밋에 포함하지 않는다. 아래 로컬 경로는 작성자 작업 폴더 기준이며, 팀원이 데이터를 열려면 해당 파일을 별도로 전달받아야 한다. 공식 출처·논문 웹 링크는 문서에서 바로 열 수 있다.

## ① 확정된 주제와 목적

**주제: 「부산 동별 119 신고 특성에 따른 맞춤형 예방안 제안」**

부산 전체의 신고 특성과 동별 인구 배경을 먼저 비교한다. 그 결과에 따라 집중적으로 살펴볼 동과 신고 유형을 좁히고, 필요한 배경자료와 기존 대응을 확인해 예방 보완 후보를 제안한다.

> 부산 전체 신고 비교 → 동별 인구 배경 확인 → 집중 검토 대상 선정 → 필요한 배경자료 선택 → 기존 대응 대조 → 예방 보완안 제안

| 항목 | 확정한 기준 |
|---|---|
| 출발점 | 어떤 신고가 어디서, 언제 반복되는가 |
| 지역 범위 | 부산 전체에서 시작하며 행정 읍·면·동을 비교 단위로 사용. 구·군은 현황 요약에 활용 |
| 기간 | 2020~2024년. 기간이 짧은 보완자료는 해당 기간에 한정 |
| 인구의 역할 | 동의 전체 연령 구성과 인구 규모를 설명하는 배경정보 |
| 집중 검토 대상 | 데이터 품질과 신고 특성을 확인한 뒤 선정. 특정 지역·유형을 미리 고정하지 않음 |
| 상권·건축·생활인구 | 대상 선정 후 필요한 경우에만 선택하는 자료 |
| 공백 판단 | 신고 특성과 관련 시설·서비스의 실제 대응 범위를 대조해 판단 |
| 최종 형태 | 직접 구축하는 부산 동별 지도 웹페이지와 근거가 연결된 예방 보완 제안 |

현재의 문제의식은 **동마다 다른 신고 양상에 대해 어디를 우선 살펴보고 무엇을 보완할지 판단할 근거를 마련하는 것**이다. 특정 동의 심각성이나 기존 정책의 실패는 아직 확인된 사실이 아니다. 모든 발생 원인을 규명하거나 지역의 모든 환경 요소를 수집하는 방향으로 확대하지 않는다.

## ② 필요한 데이터 및 실제 확보·사용 가능 현황

아래는 기존 원본 점검과 공식 출처 기록을 바탕으로 정리한 보유 현황이다. 이번 문서 작성에서 신규 전수 검사나 신고 분석을 실행하지 않았다. 경로는 프로젝트 루트 기준이며, ‘확보’는 전처리·공간 연결·해석까지 검증됐다는 뜻이 아니다.

#### 이 인구 데이터를 사용하는 의도

**신고가 반복되는 동에 어떤 연령대 주민들이 사는지 이해하고, 이후 어떤 현장 배경과 기존 대응을 더 확인해야 할지 판단하기 위해 사용한다.** 인구만으로 위험지역이나 예방책을 먼저 정하는 자료가 아니다.

| 활용 단계 | 인구자료로 확인할 내용 | 다음 판단에 연결하는 방식 |
|---|---|---|
| 신고 특성 확인 이후 | 해당 동의 전체 주민 규모와 연령별 인원·비중 | 신고 특성을 그 동의 주민 배경과 함께 설명. 연령별 인원과 비중을 함께 보며 실제 신고 대상자의 나이는 별개로 둠 |
| 집중 검토 대상 구체화 | 동별 주민 구성의 차이 | 신고의 유형·반복성·시간 특성과 함께 살펴 추가 검토 질문을 구체화. 고령층·어린이 비중만으로 대상 동을 자동 선정하지 않음 |
| 필요한 현장 배경 선택 | 주민 배경만으로 이해하기 어려운 신고 양상이 있는지 | 관련성이 필요한 경우 상권·공사현장·생활인구·특정 구간 자료를 선택. 주민과 방문자·근무자가 같다고 가정하지 않음 |
| 기존 대응 대조 및 제안 | 선택한 예방·지원 서비스의 대상과 동의 주민 배경을 함께 고려할 필요가 있는지 | 신고 특성·현장 조건·실제 서비스 범위를 확인한 뒤 보완안을 검토. 인구 구성만으로 시설 설치·순찰·돌봄 필요성을 확정하지 않음 |

보고서·지도에서는 **‘이 동에 이런 신고 특성이 나타나며, 주민의 연령 구성은 이렇다’**고 설명한다. **‘노인이 많이 사니 이 신고는 노인 사건이다’**처럼 개인 특성으로 바꾸지 않는다. 이 자료의 역할은 지역 배경 설명이며, 정책 효과 입증이나 신고의 전체 원인 규명이 아니다.

**공간 결합은 기본 자료를 연결하는 과정이며 예측모형과 양자택일할 방법이 아니다.** 현재의 동별 특성 파악과 대응 대조만으로 제안 근거가 충분하다면 예측모형을 추가하지 않는다. 입지 최적화도 설치할 시설의 목적·대상·후보지·제약을 확인한 경우에만 후속 검토한다.

### 5-1. 우선 채택할 기본 방법: 집계·시간 비교·공간 결합

**기본 분석은 ‘동별 기술통계 + 시간별 비교 + 검증된 공간 결합 + 인구 배경 병렬 비교’로 설계한다.** 이것만으로도 어떤 동의 어떤 신고를 더 살펴봐야 하는지 설명할 수 있다. 논문에 나오는 고급 기법을 모두 적용하는 것이 목표는 아니다.

| 방법 | 작동 방식과 필요한 데이터 | 만들 결과 | 검증·해석 기준 |
|---|---|---|---|
| 동별 기술통계 | 검증한 접수 기록을 동·유형·기간으로 묶어 건수와 구성비를 계산 | 동별 접수 규모, 주된 유형, 연도별 변화 | ‘동 전체 접수 중 특정 유형 비중’과 ‘부산 해당 유형 중 그 동의 비중’은 분모가 다르므로 별도로 표시. 미분류를 숨기지 않고 작은 건수의 큰 비율 변화를 함께 설명 |
| 시간별 비교 | 같은 유형의 월·요일·시간대 분포를 동별로 비교. 날짜와 원본 시간 필드 일치 여부 선확인 | 월별 추이, 요일×시간대 표, 여러 연도에서 반복되는 시기 | 관측 가능한 일수가 다르면 일평균도 병기. 특정 월이 많다는 사실만으로 계절성이 입증됐다고 쓰지 않고 여러 해의 반복 여부 확인 |
| 공간 결합 | 검증한 신고 좌표가 당시 어느 행정동 경계 안에 있는지 판정하고 동 코드를 부여 | 신고→행정동 대응표, 미연결·다중일치·경계 위 점 목록 | 좌표계를 맞추고 다중일치로 행이 늘어나는지 확인. 원본 행 수와 배정·보류 건수 대조. 이름만 같은 법정동과 행정동을 동일 취급하지 않음 |
| 인구 배경 병렬 비교 | 같은 동의 전체 연령 분포와 신고 특성을 나란히 비교 | 신고 특성과 주민 구성을 함께 보는 동별 프로필 | 주민 연령과 실제 환자 연령을 구분. 필요 시 인구 대비 지표를 추가하되 해당 유형의 노출 집단과 맞는지 검토 |

공간 결합은 새로운 위험모형이 아니라 자료 연결 기술이다. 점과 다각형의 포함·교차 관계 및 결합 방식은 [GeoPandas 공식 Spatial Joins 문서](https://geopandas.org/en/stable/gallery/spatial_joins.html)를 구현 근거로 참고한다. 공식 기술문서를 방법론 논문으로 표시하지 않는다.

### 5-2. 집중·반복의 의미에 따라 선택할 공간·시공간 방법

‘건수가 많은 곳’, ‘주변 동과 함께 높은 곳’, ‘평소와 달리 특정 시기에 몰린 곳’, ‘앞으로 수요가 예상되는 곳’은 서로 다른 질문이다. 다음 방법 중 필요한 질문에 맞는 것만 선택한다.

| 방법·참고 문헌 | 무엇을 알아보는가? | 적용 절차·필요 데이터 | 결과와 한계 |
|---|---|---|---|
| 점 분포·격자 집계 / 기본 시각 탐색 | 동 안에서 어느 위치에 접수가 반복되는가? | 좌표 정확성을 확인한 뒤 점 분포 또는 격자별 유형·기간 집계. 격자 크기는 위치 정밀도와 관측량을 고려해 비교 | 세부 위치 검토 후보. 격자 경계·크기에 따라 결과가 달라질 수 있으며 통계적 유의성이나 원인을 자동 입증하지 않음 |
| 국지적 공간 연관성(LISA, Local Moran’s I) / 문헌 P1 | 높은 값의 동이 높은 값의 이웃과 모이는가? 주변과 다른 동은 어디인가? | 비교할 동 지표 하나를 정하고 인접 또는 거리 기반 이웃을 정의. 국지 통계와 순열검정을 검토 | 높은 값끼리 모인 유형, 낮은 값끼리 모인 유형, 이웃과 다른 유형을 구분. 이웃 정의·작은 분모·다중검정에 민감. 높은 접수량의 군집이지 곧바로 위험·대응 공백이 아님 |
| 시공간 순열 스캔 통계 / 문헌 P2 | 원래 지역별 규모와 전체 시간 변동을 고려해도 특정 지역·시기에 이례적으로 접수가 몰리는가? | 위치·날짜가 있는 동일 정의의 접수 자료로 공간·시간 탐색창을 설정하고 순열 기반 비교 | 일시적 집중 후보. 장기적으로 항상 많은 동을 찾는 방법과 목적이 다름. 누락·기록 체계 변화에 민감하고 도시 전체에서 동시에 증가하는 양상은 별도 시간 비교 필요 |
| 시공간 커널 밀도 추정(stKDE) / 문헌 P3 | 과거 위치·시간 패턴으로 다음 시점의 수요 분포를 추정할 필요가 있는가? | 과거 위치 주변에 부드러운 밀도를 만들고 예측 시점에 유용한 관측에 시간 가중치를 부여. 좌표·시간·검증 기간 필요 | 미래 시간대별 공간 수요 분포. 단순 과거 밀도 지도와 구분. 대역폭·시간 가중치와 시간순 평가 필요. 현재는 예측 필요성이 확인될 때만 선택 |

**권고:** 우선 기본 비교로 후보를 좁힌다. 인접 동까지 함께 검토해야 하면 LISA, 특정 시기의 이례적 집중이 핵심이면 시공간 스캔, 미래 수요가 실제 의사결정에 필요하면 stKDE를 검토한다. 세 방법을 한꺼번에 수행하거나 결과가 비슷하다는 이유로 같은 분석이라고 설명하지 않는다.

후보를 좁힌 뒤 LISA를 검토하더라도 계산·검정의 비교 범위는 원칙적으로 부산 전체 동을 유지한다. 선택된 후보 동만으로 이웃과 기준 분포를 다시 만들지 않는다. 연구 질문상 범위 변경이 필요하면 변경 이유, 이웃 정의, 비교 모집단과 다중검정 범위를 명시하고 기존 결과와 구분한다.

### 5-3. 대상 선정 후 배경과 대응을 검토하는 방법

| 방법·참고 문헌 | 작동 방식 | 우리 작업에서의 적용 조건 | 해석 가능한 범위 |
|---|---|---|---|
| 국지적 공위치 지수(LCLQ) / 문헌 P4 | 한 종류의 점 주변에 다른 종류의 점이 전체 구성에 비해 상대적으로 많이 나타나는지 국지적으로 비교하고 모의검정 | 선택한 신고 유형과 관련 업종의 점자료가 같은 기간·공간 기준으로 확보됐을 때만 검토. 이웃 거리·점 범주·비교 모집단을 명시 | 특정 신고와 특정 업종의 공간적 동반분포. 신고→업종과 업종→신고의 방향이 다를 수 있음. 가까운 업소가 원인이나 신고자의 방문처라는 뜻은 아님 |
| 생태학적 추론의 한계 점검 / 문헌 P5 | 집단 단위에서 보이는 관계와 개인 단위 관계를 구분 | 모든 인구 배경 비교와 보고서 해석에 적용. 모델 실행 기법이 아니라 추론 범위를 점검하는 근거 | 고령인구 비중과 구급접수의 지역별 동반 양상까지 설명 가능. 실제 고령 환자 수·개인 위험·고독사 건수는 생성 불가 |
| 기존 대응 범위 대조·접근성 | 관련 수요 위치와 시설·서비스의 대상·운영 시간·접근 조건을 대조. 필요 시 도로망 이동거리·시간 계산 | 대응 분야 선정 후 시설 위치뿐 아니라 이용 가능 여부와 운영 조건 확인. 거리·시간 기준은 공식 서비스 기준 또는 근거 있는 시나리오로 구분 | 접근·운영 조건별 추가 검토 지역. 지도상 가까운 시설이 실제 서비스를 제공하거나 여유 인력이 있다는 뜻은 아님 |
| 최대 커버 입지모형(MCLP), 최소 시설 커버모형(LSCP) / 문헌 P6·P7 | MCLP는 정해진 시설 수로 포함되는 수요를 최대화. LSCP는 정해진 도달 기준으로 전체 대상 수요를 포함하는 데 필요한 시설 수를 최소화 | 보완 필요성 확인 후 수요지·설치 후보지·기존 시설·이동비용·서비스 기준·시설 수 또는 예산 제약 확보 | 설치 후보 시나리오와 미포함 수요 비교. 단순 커버모형에는 수용능력·동시 수요가 자동 반영되지 않음. 시설 입지와 순찰 경로 최적화는 별개 |

상권 자료가 있다고 LCLQ를 수행하거나, 시설 위치가 있다고 입지모형을 수행하지 않는다. 먼저 어떤 신고 특성을 설명하거나 어떤 보완 결정을 지원할지 정한다. 비교할 기존 서비스 근거가 없으면 ‘대응 공백’ 대신 ‘운영 범위 추가 확인 필요’로 남긴다.

### 5-5. 분석 선택과 검증 계획

| 구분 | 적용 판단 | 검증 계획 |
|---|---|---|
| 기본 분석 | 동별 집계·시간 비교·공간 결합·인구 배경 비교를 먼저 설계 | 원본→분류→동 집계 합계 대조, 미연결 비중과 연도별 품질 차이 확인 |
| 공간·시공간 확장 | 기본 비교로 남은 질문이 있을 때 P1 또는 P2 등을 선택 | 이웃·공간 크기·시간창 변경에 따른 결과 비교, 반복 검정의 보정 방식과 검정 대상 사전 명시 |
| 배경 연관 분석 | 선정한 신고 특성과 해당 배경자료의 연결 필요성이 확인될 때 P4 검토 | 분기·업종 체계·좌표 정합성 확인, 이웃 정의에 따른 변화 보고. 유의한 곳만 골라 전체 결과를 숨기지 않음 |
| 입지 분석 | 시설 보완안과 설치 조건이 구체화됐을 때 P6·P7 검토 | 같은 시설 수·후보 조건에서 기존 배치 또는 단순 대안과 비교. 포함되는 과거 신고와 이동거리 변화는 피해 감소와 구분 |
| 예측 분석 | 미래 수요가 제안에 필요하고 시간순 검증이 가능한 경우에만 P3 검토 | 단순 과거 평균·동일 계절/시간대 기준과 비교. 학습·조건 선택·평가 기간 분리. 평가 기간을 보고 후보·가중치를 재조정하지 않음 |

예측을 선택한다면 2020~2022년 학습, 2023년 조건 선택, 2024년 최종 평가를 **검토 예시**로 둘 수 있다. 실제 분할은 분류·경계의 비교 가능성과 관측량을 확인한 뒤 확정하며, 2023~2024에만 있는 생활인구를 이전 학습기간에 만들어 넣지 않는다. 좋은 성능이 나오지 않으면 예측을 최종 서비스에서 제외할 수 있다.

**이번 단계의 결론:** 기본 기술통계와 공간 연결 설계를 우선 확정한다. 공간 집중·상권 연관·시설 입지·미래 예측은 각각 다른 의사결정 질문에 필요한 경우에만 확장한다. 이번 보강은 문헌 확인과 설계 작성이며 실제 신고 분석·통계검정·예측모형 실행은 하지 않았다.

## ⑥ 대응의 공백을 판단하기 위해 필요한 근거

| 근거 단계 | 필요한 내용 | 가능한 표현 |
|---|---|---|
| 신고 특성만 확인 | 반복되는 유형·위치·시기와 자료의 신뢰성 | ‘추가 검토가 필요한 동·신고 유형’ |
| 관련 배경까지 확인 | 해당 시점의 인구·선택 업종·현장 환경과의 동반 양상 | ‘이러한 지역 배경과 함께 살펴볼 필요가 있음’ |
| 시설 위치만 확인 | 관련 시설의 위치와 명부 기준일 | ‘접근성 또는 운영 범위 추가 확인 필요’ |
| 대응 적용 범위까지 확인 | 대상·운영 시간·이용 조건·도달 범위 등 제안에 필요한 정보 | 확인한 조건에 한해 ‘이 지역·시간·대상에 대한 보완 검토 근거가 있음’ |
| 근거 부족 또는 자료 시점 불일치 | 운영 이력·접근 조건·가용량 등 미확인 | 공백으로 확정하지 않고 확인 과제로 제시 |

과거 신고 양상과 현재 시설을 대조한다면 ‘현재 보완안을 검토하기 위한 참고’로 시점을 명시한다. 현재 명부로 과거 대응 부족을 입증하지 않는다. 데이터로 보완 필요성이 확인되지 않으면 억지로 설치·순찰·돌봄안을 만들지 않는다.

## ⑦ 예상 산출물과 기대효과의 검증 방법

| 예상 산출물 | 제공할 내용 | 검증 방법 |
|---|---|---|
| 데이터 현황·품질표 | 원본 출처, 기간, 컬럼, 결측, 공간 연결 상태와 제외 사유 | 원본·입력 명세·집계 대상 대조, 연결 성공·실패 건수 보존 확인 |
| 부산 동별 신고·인구 현황 | 신고 특성과 전체 연령 배경을 구분해 표시 | 동 집계와 전체 합계 대조, 계층·성별 중복 합산 확인 |
| 집중 검토 후보표 | 후보 동·유형, 선정 근거와 불확실성 | 기준 공개, 특정 연도·공간 단위 변경에 따른 후보 안정성 검토 |
| 기존 대응 대조표 | 시설·서비스의 위치·대상·시간·확인하지 못한 항목 | 공식 운영 근거와 시점 대조, 위치와 서비스 범위 구분 |
| 예방 보완 제안 | 어느 동에서 무엇을 검토할지와 근거 | 신고→배경→대응→제안의 근거 연결 및 제안별 미확인 조건 검토 |
| 직접 구축할 지도 웹페이지 | 부산 동 지도, 연도·유형·시간 필터, 인구 배경, 선택한 대응정보, 후보 근거·출처 | 원본 집계와 화면 값 대조, 필터 적용 확인, 동 선택→근거 확인 사용 과제 점검 |

기대효과는 **우선 검토 지역을 근거에 따라 선정하고, 필요한 보완과 추가 확인 사항을 이해하기 쉽게 제공하는 것**이다. 신고 감소·인명피해 감소는 현재 검증할 수 있는 성과로 약속하지 않는다. 지도에서는 동 집계를 기본으로 하고, 개별 위치의 공개 가능 범위는 데이터 이용 조건과 위치 정밀도를 확인한 뒤 결정한다.

## ⑧ 분석 시작 전 해결해야 할 사항

### 공통 분석 시작 조건

- [ ] 2020~2024 신고·인구 입력 파일과 원본 보존 기준을 확정한다.
- [ ] 부산 판정, 접수 1건의 의미, 중복·처리 상태·분류의 취급 기준을 기록한다.
- [ ] 좌표 정의·좌표계·사용 기준과 동 연결에 필요한 당시 경계·코드를 확인한다.
- [ ] 지역·좌표·시간·분류 결측 및 불일치를 어떻게 분리할지 정한다.
- [ ] 행정동·법정동과 연도별 변경을 확인하고 비교 가능한 지역·기간을 명시한다.
- [ ] 인구의 연말 기준과 전체 연령 유지 원칙, 인구 대비 지표의 적용 조건을 정한다.
- [ ] 단계별 집계 항목과 집중 검토 후보 선정 기준의 확정 절차를 문서화한다.

### 대상 선정 후 해결할 조건

- [ ] 배경자료마다 필요한 이유·사용 기간·연결 단위·한계를 명시한다.
- [ ] 제안에 필요한 기존 대응 정보와 확보하지 못한 운영 조건을 구분한다.
- [ ] 공백으로 판단할 근거와 추가 확인 대상으로 남길 기준을 정한다.

### 모든 단계에서 유지할 해석 원칙

- 지역 인구 비율로 개별 환자 나이나 연령별 신고 수를 생성하지 않는다. 어린이·고령층을 살피더라도 중간 연령대를 제외하지 않는다.
- 구급신고를 고독사로, 고령인구가 많은 동의 신고를 노인 신고로 단정하지 않는다.
- 접수 건수와 실제 사건·출동·환자 수를 구분한다.
- 주변 업종·공사 기록과의 근접·동반 양상을 인과관계로 해석하지 않는다.
- 결측값, 시간×연령 교차값, 과거 운영 이력을 임의로 생성하지 않는다.
- 확인된 사실·검토 가설·추가 확인 사항을 구분한다.
- 특정 시설·활동·인력 배치를 미리 정하지 않으며 과거의 다른 주제를 다시 끌어오지 않는다.

이 계획의 다음 작업은 **공통 필수 데이터의 미확인 정의와 동 연결 조건을 해결하고 점검 결과를 확정하는 것**이다. 상권·건축 등 선택자료의 확장 수집, 본 분석, 예측모형, 웹 구현과 제출서류 작성은 각각 필요한 단계에서 진행한다.
